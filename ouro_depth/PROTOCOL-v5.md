# V5：随机无梯度前缀 + 固定梯度窗口（progressive）训练能否让额外循环有用

状态：2026-09-13 定稿，训练启动前冻结。用户已授权自主设计并使用可用 GPU。本协议是新的假设与新的确认，不追认任何历史门槛。

## 1. 问题与假设

历史证据（V2/V3 fixed4、extension 对照）反复显示同一现象：仅在 T4 训练的模型，在未见 d9–12 上 T6 明显优于 T4（35–53% vs 10–15%），但 T12/T16 回落到接近随机（8–10%），且简单题 d1/d2 在 T16 也退化（88%/69%）。所有已做的深循环训练（V3 conditional/independent、V4 fixed8、extension R6/R8）都只改变**前向循环数与终点监督位置**，并且全部使用完整 BPTT；没有一次检验过针对“继续计算 + 保持答案”的训练信号。

主假设 H1：额外循环失效的主要机制是**过度计算漂移**（overthinking）——循环块在答案已经可读之后没有被训练过继续保持或修正状态。若训练时先运行随机长度 n 的无梯度前缀循环，再从该状态出发运行固定 K=4 轮有梯度循环并只监督终点（Bansal 等 2022 的 progressive loss；Huginn 预训练的 R/K 采样即此思想），共享块将学会 (a) 从任意中间状态继续推进，(b) 已解出时保持答案，从而使“循环数—难题准确率”曲线在训练范围内外都不再回落，并且 T16 在未见 d9–12 上超过同模型 T8 以及所有浅训练对照出口。

对照假设 H2（梯度窗口）：同一随机总深度分布下改用完整 BPTT（K=T），如果同样有效，则收益来自深度采样而非截断窗口；如果反而退化（与 V3/extension 一致），则截断窗口是必要成分。

可否定 H1 的结果：prog 臂 T16 不高于自身 T8，或不高于 control/初始化在任一预定出口的最高值，或 T32 相对 T16 再次回落。

## 2. 共同设置

| 项目 | 取值 |
|---|---|
| 初始化 | V3 fixed4 最终 `runs/v3-fixed4-s20260914/checkpoint-1566`（与 extension 相同字节，SHA `fd5b1583…bc75`），重置 Adam |
| 训练数据 | `data/extension-candidate-pointer/train.jsonl`，24,000 题，d1/2/3/4/6/8 各 4,000，25 节点 |
| 批次流 | 复用 extension 的 v4 共享同质流（seed 20260916）：每 6 批各难度一次，B16 / micro 8，固定 padding L=208 |
| 更新数 | 每臂 384 |
| LR | `1e-6·min(u/24,1)`，AdamW(.9,.95)，wd .01，clip 1；FP32 参数/Adam，BF16 autocast，逐层激活重计算 |
| 可训练参数 | 共享 24 层 decoder + 末 RMSNorm，1,233,324,032；embedding/head 冻结 |
| 损失 | 仅终点全词表答案 CE；无多出口、无浅层辅助项 |
| 端点 | update 192、384 各保存检查点并评估 DEV；主终点 384 |
| 推理出口 | T ∈ {4, 6, 8, 12, 16, 24, 32}，单次展开收集 |

每次更新的核心工作代理为 `B·L·24·(T + 3K)`：无梯度前缀每轮 1 单位，有梯度轮前向+重算+反向记 4 单位。它不是实测 FLOPs；同时记录实际 GPU 秒与峰值显存。

## 3. 臂

| 臂 | 每次更新的总循环 T | 有梯度末段 K | 说明 |
|---|---|---|---|
| control | 4 | 4 | 复用已完成的 `runs/extension-control-s20260916`（同流、同 LR、384 更新）；只补评新出口 |
| prog16 | 预先抽样 U{4,…,16} | 4 | 主候选 |
| prog16b | 同分布，另一抽样种子 | 4 | 检验深度抽样噪声 |
| prog32 | 预先抽样 U{4,…,32} | 4 | 检验训练深度范围 |
| full16 | 与 prog16 逐更新完全相同的 T 序列 | T（完整 BPTT） | 隔离梯度窗口 |

所有臂在同一更新位置使用同一批样本与同一 LR；每次更新的 T、K 在计划文件中预先冻结，运行时不得依赖 loss 或 DEV。control 与 prog16 构成 T∈{4} 对 U{4..16} 的对比；prog16 与 full16 构成 K=4 对 K=T 的对比。四条新臂各占用 reds-lab GPU4–7 之一。

预期核心代理：control 每更新 16 单位·B·L·24；prog16 均值 22；prog32 均值 30；full16 均值 40。本实验按更新数与样本匹配，**不按工作量匹配**；control 是较便宜的臂。

## 4. 评估数据与分组

- DEV：`data/extension-candidate-pointer/dev.jsonl`，1,280 题，d1/2/3/4/6/8/9/10/11/12 各 128。主组为未见 d9–12（n=512）。初始化、control384 在 T4/6/8/16 的既有结果保留，并在同一 DEV 上补评全部七个出口。
- 密封确认：`data/extension-candidate-pointer/test.jsonl`，5,120 题，至今未评分；主组 d9–12 共 2,048 题。仅在 DEV 门槛通过后一次性评分。
- 探索性探针（不计入门槛）：新生成 d13/14/15/16，33 节点图，每跳 64 题。它同时改变链长与图规模，只作“更长链 + 更大上下文”的描述性观察。

## 5. 预先固定的判断（对每个 progressive 臂 X，主终点 384，主组 d9–12 全词表正确率）

1. **额外循环有效：** `A(X,T16) − A(X,T8) > 0`。
2. **训练归因：** `A(X,T16) − A(control,T16) > 0`。
3. **超过最强浅训练出口：** `A(X,T16) ≥ max{A(control,T), A(init,T) : T∈{4,6,8,12,16,24,32}} + 5pp`。这是投入确认的实用余量。
4. **简单题保持（hold）：** d1、d2 在 T4 各 ≥98%，在 T16 与 T32 各 ≥95%。
5. **已学难题在深出口不被破坏：** d6、d8 在 T8、T16、T32 各 ≥90%。
6. **无过度计算回落：** `A(X,T32) ≥ A(X,T16) − 2pp`。

六项同时成立才算 DEV 通过。d6/d8 在 T4 的变化完整报告；下降超过 5pp 记为“浅层代价”，不是门槛失败，但结论必须写明。每跳（d9/10/11/12）结果分别保留，不只报汇总。

主候选是 prog16；prog16b 用于确认同向；prog32、full16 为机制对照。若 prog16 通过而 prog16b 不通过，只报告为不稳定信号，不进入确认。

**修订（2026-09-13，训练启动后、任何 V5 模型 DEV 结果被读取之前；依据独立统计评审）：** 判断 1–3 的点规则在真实效应恰为 5pp 时只有约 50% 通过概率，两臂联合约 25%，失败时对 H1 几乎没有证据力。因此改为：

- 判断 1–3 各自的通过条件是 **配对增益 > 0 且三项 exact McNemar 经 Holm 校正后 p < 0.05**（每臂一个家族）。
- 5pp 不再是门槛，而是“实用余量”标志：`A(X,T16) − 最强基线出口 ≥ 5pp`。**开封密封 test 需要** prog16 六项判断全过 **且** 实用余量成立 **且** prog16b 判断 1–3 的三个点增益同号为正（方向一致），prog16b 不要求六项全过。
- 中间区措辞：若 prog16 的 T16 超过最强基线出口但差值不显著或不足 5pp，报告为“正向但未达进入确认的余量”，既不是 H1 被否定，也不是通过。
- 权威数值：所有 V5 比较只用本轮同一评估代码、单次展开七出口的新评估文件（control384 与初始化亦重评）；旧四出口结果只用于一致性核对。
- 晋级规则：只有 prog16 是预先声明的候选。prog16 失败而 prog16b/prog32/full16 通过，记为新的开发线索，需要另行声明后才能确认，不能在本轮开封 test。
- H2 判定：full16 与 prog16 在 T16 逐题配对（主组）。full16 同样通过判断 1–3 且 6 → 截断窗口不是必要成分；full16 未通过判断 1 或 6 而 prog16 六项通过 → 截断窗口是必要成分；其余情况记为不确定。
- 取整：所有阈值按比例值比较（例如 5pp 即 `gain ≥ 0.05`），不做整数取整。

**第二次修订（同日，评审工作流完成后、384 步结果读取前）：**

- 结论分级（措辞规则，不改变开封 test 的条件）：**hold 级** = 判断 4、5、6 成立且 `A(X,T16) ≥ 最强基线出口 − 2pp`，措辞为“深出口保持已学答案”；**continue 级** = 判断 1–3 成立，措辞为“额外循环完成了新的推理”。只有 continue 级才对应研究目标第一阶段。
- 逐跳机制核查（次级，不作门槛）：对 d9/10/11/12 各自找出基线（初始化、control）在七个出口中的逐跳最优出口，报告其平均值作为第二参考线，并做 prog 臂 T16 对该逐跳最优出口的逐题配对。若汇总判断通过但 d11、d12 都没有显著超过其逐跳最优基线，结论只能写“深出口整合/保持了基线在不同出口已能解出的答案”，不得写“额外循环解出了新长度”。
- 判断 4–6 是观测阈值（n=128 单元），不是统计检验；协议接受其在真值刚好达标时的误判风险，结果按原样报告。

以上规则在 `compare_v5_predictions.py` 中固化，并有合成数据测试。

## 6. 统计

逐题配对：错→对 / 对→错、exact McNemar、既有 Bonferroni–Wilson 近似 95% 区间；判断 1–3 构成主家族，Holm 校正。DEV 用于决定是否确认；确认在密封 test 上用相同的三个主对比（prog16 T16 对自身 T8、对 control T16、对 control/init 最强出口——该出口由 DEV 事先指定，不在 test 上重选）。

**修订（评审后、test 未评分）：** 确认的约束性判据是三项对比各自 **增益 > 0 且 exact McNemar 经 Holm(3) 校正 p < 0.05**，与 DEV 规则一致。Bonferroni–Wilson 区间在 n=2048、真实 5pp 时“下界 > 0”的功效只有约 0.7–0.8，因此只作描述性报告，不再作为成立条件。

## 7. 停止与不得为之

- 出现非有限 loss/梯度、OOM 或检查点损坏：停止并保留现场；不自动重试、不改设置续跑。
- 门槛失败：不延长更新、不换出口、不换检查点、不调 LR；如实报告并在 FINDINGS-v5.md 中记录负结果。
- 不读取密封 test 的答案用于任何设计决定；不把 33 节点探针结果当作主结论。

## 8. 解释边界

- 初始化是按既有 DEV 表现选出的“已学会 d≤8 的模型”，因此这是**续训干预**的因果检验，不是“从零训练即可得到”的证明；完整归因需要下一阶段从 one-hop 初始化重跑整条课程。
- prog16b 只改变深度抽样种子，不改变初始权重与样本流，不能替代跨初始化的重复。
- T4 出现在训练流中；d9–12 是未见链长而非未见图规模。
- 单 seed 的 DEV 通过只是开发证据；即便确认通过，也不等于学会自适应停止。
- **机制边界（依据独立机制评审，训练启动后、结果读取前补记）：** Ouro 每轮只把归一化后的隐状态送回，没有 Huginn/Bansal 式的输入重注入。无梯度前缀把 h_n 视为常量，损失无法直接惩罚“前缀丢失了题目信息”，只能训练末段 K 轮从幸存信息中读出答案；full16（K=T）臂是让梯度穿过前缀的对照。训练集 d≤8 在初始化 T4 已基本解出，所以训练信号主要教“保持/重推”，而“继续推进”只能通过 d9–12 在更深出口的泛化间接检验。因此本实验回答的是“无输入注入的 Ouro 上，截断窗口的 progressive 信号是否足以让额外循环有用”，不是复现 Bansal/Huginn 的完整配方；首要替代解释预先登记为“无注入时该信号不足以学会保持”。输入注入臂与逐轮状态漂移诊断列为后续候选。

## 9. 若通过之后

冻结 prog16 的 384 检查点；用 `launch_v5.py confirm` 一次性在密封 test 上评估 prog16、control384、初始化的七个出口；写入 CONFIRMATION-v5。随后的第二阶段候选：从 one-hop checkpoint-416 以 progressive 信号重跑 V3 fixed4 的完整课程，与已有 V3 fixed4 对照，检验“训练全程使用该信号”的效果；以及在从零训练的小型循环 Transformer 上重复同一 2×2 设计以排除预训练深度先验。
