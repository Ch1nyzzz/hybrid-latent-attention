# Huginn 固定训练深度 32 对 64：正式实验草案

后续方向以 [RESEARCH_OBJECTIVE.md](../RESEARCH_OBJECTIVE.md) 为准。本文件保留为未采用的固定深度对照草案；其中对最佳基线的要求不是整个研究的先决条件。下一项训练方法需围绕“训练新增循环继续推进推理”重新定稿，不由本草案或准备工具自动启动。

2026-09-13。**草案，未采用、未生成数据、未启动。** 只讨论当前两个固定深度臂；不是循环深度课程，也不是难度与深度配对实验。本文件不改变已经登记的共同适配或任何 Ouro 协议。

## 1. 问题与启动前提

问题是：从同一个可用初始化出发，固定训练到 64 轮，相比固定 32 轮，是否在相同训练资源下提高未训练长度 d9–12 的绝对正确率，并使额外推理循环本身有益？不能用自身浅出口退化造成的差值，或只战胜已经退化的同 T64 对照来回答。

Ouro extension 已给出具体反例：其最终 T16 比自身 T4 高 6.25 pp，却低于自身 T8 2.34 pp，并低于曝光对照的 T6 26.95 pp；它没有通过原登记门槛。因此本实验从开始就冻结中间出口、同曝光对照和绝对性能检查，不在失败后增加出口寻找成功。Huginn 默认平均 32 轮预训练且采样有长尾，64 轮不应被称为“从未见过的深度”。

启动必须等待 [HUGINN-SHARED-ADAPTATION.md](HUGINN-SHARED-ADAPTATION.md) 的**最终 update256** 自然完成，并在原 256 道校准 DEV 上于 T32、T64 都达到 d1≥95%、d2≥80% 的 unrestricted next-token accuracy。只用最终 256 权重；不使用 update128 或训练题记忆结果替代。未通过则不启动本实验，不延长共同适配。此处不推断适配当前运行状态。

通过后冻结同一权重、原始官方代码 revision `bb6621b65e90b6a4b9b29ef88dc83866d450470c`、native BOS 接口、tokenizer、数据/计划与评估种子；两臂都**重置 AdamW、scheduler 和计数器**。共同适配的 256 更新/4096 实例成本单列。结论适用于“经过 R32 任务适配的 Huginn”，不能称原始预训练模型的直接比较。

## 2. 训练设置与实例

| 项目 | F32 | F64 |
|---|---|---|
| 固定训练循环 R / 反传窗口 K | 32 / 8，显式 `[24,8]` | 64 / 8，显式 `[56,8]` |
| 最终有效更新数 | 1200 | 780 |
| 难度分布 | 全程 d1/2/3/4/6/8 均衡 | 同一完整 batch 流的前 780 次 |
| 有效批量 | 16，microbatch2 × accumulation8 | 相同 |
| 参数/优化器 | 全部 3,564,976,800 参数 FP32；FP32 AdamW，BF16 autocast | 相同 |
| 目标与 checkpoint | 仅训练出口最后有效 prompt 位置的全词表 CE；官方 native checkpoint | 相同 |

不改变官方递归核心、归一化、初态分布、截断反传边界，不混入 full BPTT、辅助浅出口损失、蒸馏、CoT 或自适应退出。标量 `num_steps` 会绕过所需循环 core 梯度，训练必须显式传二段窗口。保持无 cache、`test_time_noise=0`。不同 R 的无梯度前缀长度不同；本实验检验 **固定 K8 下增加训练循环**，不宣称检验长程完整梯度的价值。

具体计算可写为 `e=Pθ(x)`、`z=stop_gradient(Fθ^(R−8)(z0,e))`，再对 `−log pθ(y | Fθ^8(z,e))` 求梯度。停止梯度只截断递归状态前缀；后八轮仍接收可微的 `e`，所以 prelude、核心、adapter、coda/head 都可以更新。这是截断梯度，不能称完整 R 轮目标的精确梯度。R64 对 R32 改变的是被优化的深处状态分布与前向计算，反传窗口同为八轮；一个循环包含整个共享核心，也不能等同一条图边。深循环是否学到可迁移的迭代求解，必须由预定难题和强基线结果判断，有限梯度或稳定范数本身不能证明。

主训练 seed 与 sampling seed 暂都建议 `20260917`，作为离线准备选择，尚未采用。新 `huginn_depth_plan.py` 可只从训练行元数据准备固定计划；计划 fingerprint 不代表训练授权。

建议沿用 AdamW betas=(.9,.95)、weight_decay=.01、clip_norm=1.0。草案 LR 为 `1e-6 × min(t/24,1)`，t 从 1 开始，24 次 warmup 后恒定；这是相同更新编号的共同前缀，不按各臂预算百分比做独立 cosine。于是同曝光 update780 的样本和逐更新 LR 完全相同，F32 的额外 420 次只是延续。1e-6 是保守的全参数后训练选择，**不是已经证明的 Huginn 最优 LR**；采用时一次冻结，不根据主 DEV 单臂调 LR。与早期建议中的 1e-5/各臂归一化进度相比，这里优先保护适配初始化和同曝光可解释性；跨模型的优化不足仍是失败时须保留的解释。

每 6 个同质难度 batch 恰含六种 d 各一次，顺序在训练前生成；每种 d 内只做固定种子随机排列。共同前 780 更新使用完全相同实例/顺序，额外 420 更新仅由 F32 消费。不能按答案、loss 或 DEV 调整难度频率。两臂在模型 construction 后设置同一固定训练 seed，保留官方 native `initialize_state`，使用相同 batch 划分和 L256，不向正式 CUDA 训练外部注入 `input_states`。固定显式 `[24,8]` / `[56,8]` 绕开随机 depth sampler；在无 cache、attention dropout=0、`test_time_noise=0` 下，循环本身不应消耗随机数，因此**预期**同曝光前缀的初态随机流相同，尚未证实。主实验工程准备需增加一次 tiny 原生随机 R32/R64 两种窗口的 RNG 消耗与初态配对验证，并对实际首批记录作有限核对；不改变 model/core API，也不引入外部训练 latent 机制。恢复保存 sampler/optimizer/RNG/计数状态。评估仍采用下节已有配对 helper。

拟使用一个新的独立数据批次，原 25 节点单环、双字母标签、随机边序、八选一 prompt 完全不变：

- train 24,000：六种训练 hop 各 4000。F32 实际使用 19,200 个唯一实例、每 d 3200；F64 使用共同前缀 12,480 个、每 d 2080。其余 4800 不因观察结果追加使用。
- DEV 1280：d1/2/3/4/6/8/9/10/11/12 各 128；主组 d9–12 共 512。
- 独立确认 3072：d9–12 各 512，共 2048 个 primary；d1/2/6/8 各 256，共 1024 个保持/任务学习检查实例。d3/4 在完整 DEV 披露，不增加没有独立问题的确认成本。

离线数据准备模块预选 data seed=`28621`、eval seed=`28622`，仍未采用或生成实际数据。

合计准备 28,352 个新图身份，所有分层 A–H 精确均衡。内部及与既有研究批次/共同适配实例图身份不重叠；旧 sealed 仅可提取 `instance_key` 排除重叠，不能读答案挑题。独立确认集在最终 DEV 决定前保持封存。本草案没有生成、打开或评分任何研究实例。

正式计划准备时必须由远端固定版本 tokenizer 编码新 train/DEV，验证 native BOS、答案边界、右 padding 和长度；暂定 L256，复用已有 B2×8/L256 容量证据。若新批次超过 L256，在任何研究训练/评分前暂停定稿并重新计算预算，不截断事实、不按长度删题。

## 3. 工作量与完整六 batch 预算

沿用 [既有推导](../artifacts/huginn-training-budget-derivation.json)：在有效 B16、L256、K8 下，令

`A = 2BL·1,637,349,120 + 16BL²·5280`

`B_other = 2BL·1,927,622,400 + 16BL²·5280`

则每次更新代理 `C(R)=(R+3K)A+3B_other`。`R+3K` 包含无梯度前缀、后缀前向、native checkpoint 重计算与约两倍前向的反向；prelude/coda/head 不做每轮 checkpoint。head dense 投影计一次，绑定 embedding 不再算第二次词表 dense matmul。

**这是统一工作量代理，不是实测 FLOPs。** 保留平方 attention、反向约两倍、checkpoint 提前结束、norm/softmax/lookup/optimizer 带宽遗漏等已有局限，另记录实际 GPU 秒、峰值显存与有效/填充 token。

| 端点 | 更新 / 六 batch 块 | 每 d 曝光 | 累计代理 |
|---|---:|---:|---:|
| F32 同曝光对照 | 780 / 130 | 2080 | 626,914,758,544,588,800 |
| F32 最终 | 1200 / 200 | 3200 | 964,484,243,914,752,000 |
| F64 最终 | 780 / 130 | 2080 | 963,918,380,924,928,000 |

两臂共有预算上限 `1200·C(32)`，F64 取不超过上限的最大完整六 batch 数。它少用 **0.058670%**，不隐藏为精确相等；这微小差额保守地不利于 F64。旧建议向上取 786 会超出 **0.710109%**，这里明确弃用。预定 780 是完成计划，不是达到任意工程 cap 后假装预算完成。

两臂合计 `1,928,402,624,839,680,000` 代理单位；另计共同适配 `205,756,638,701,813,760`。同曝光比较 F64-780 对 F32-780 回答固定样本/更新前缀下的差异，其 F64 工作量高 53.7559%；最终 F64-780 对 F32-1200 回答近似等工作量差异。两种解释分别报告。

## 4. 只保留 T32 / T48 / T64

主候选 **始终为最终 F64/T64**：64 是该臂预先规定的训练出口，也是相对预训练常用 32 轮的两倍出口，因而直接回答训练深度问题。T48 检查中间出口强基线及 48→64 的边际价值。**删除 T96**：当前没有独立的 96 轮假设，额外成本不能用来扩大寻找成功的范围；结果不好也不追加 96。

四个固定权重端点各对完整 DEV 只评分一次，均评 T32/48/64：共同 initializer、F32-780、F32-1200、F64-780。F32-780 是预定同曝光对照，不是可选中途峰值；不评其他研究 DEV 中途点。正常训练 loss/工程状态可观察，但不能改 LR/预算、替换端点或挑权重。

复用 `huginn_evaluation.paired_depth_logits`：按实例 ID 和一次冻结 eval seed，在官方分布下生成 FP32 初态；同一实例在所有权重和出口使用相同实际状态，固定 padding，不随 batch/顺序变动。`eval()`、`no_grad()`，保留调用者 RNG。主分析只有一个预定 draw，不追加随机 draw 救结果；未来多 draw 不是独立图实例。

原始 canonical next-token 正确率为唯一决策指标；裸字母、非 canonical token、restricted choice、NLL、answer mass、tie 和输出位置只是诊断。Huginn 的 space-prefixed A–H token 为 `[394,446,417,533,513,445,590,482]`，采用前以 pinned tokenizer/编码收据绑定，不能复用 Ouro token ID。

## 5. DEV 选择与独立确认：最多三个主比较

所有选择仅使用四端点完整 DEV 的 d9–12。

1. 从 **initializer、F32-780、F32-1200 各 T32/48/64** 共九个固定基线里，以 primary 正确数最大者选 `b*`；平手先低 T，再 initializer→F32-780→F32-1200。包括曝光对照，防止 F32 继续训练退化制造“收益”。
2. 从最终 F64 的 T32、T48 选正确数较大的浅出口 `a*`；平手取 T32。
3. 固定三个必要比较：`F64/T64 − b*`（强基线实用收益）、`F64/T64 − F32-1200/T64`（同推理成本的训练收益）、`F64/T64 − F64/a*`（额外循环收益）。如果前两项重复，只检验一次。T32→64 及 T48→64 均完整披露。

最终 DEV 值得进入确认须同时满足：

- F64/T64 高于九基线中的最高值至少 **5 pp**，且高于自身 T32 和 T48。DEV 不要求 CI 排除 0；512 题不承担最终确认的检验功效。
- 浅出口代价单独披露：报告 F64/T32 的 primary 正确率相对 initializer、F32-780、F32-1200 各 T32 的全部差值，并标记是否下降超过 **2 pp**。这不是首阶段成功的额外门槛；“候选深出口须超过所有强基线”的绝对性能条件已防止仅靠自身浅出口退化制造成功。困难题的浅出口保持属于未来预算自适应的另一项要求，不能与当前深循环绝对收益混为一谈。
- 候选 F64 的 d1≥95%、d2≥80% 在 T32 与 T64 都满足原 readiness；d6、d8 在 T64 均≥70%。完整披露 F32 的同项结果；F32 若任务未学会，应明确限制对照的能力，不以选择内准确率遮蔽。

未满足就报告该配置在固定预算下没有完成研究目标，确认集封存，不延长训练、不调低门槛、不改选 T48。这里仅有一个 5 pp 实用增益门槛和继承的简单/困难任务能力检查；困难题浅出口代价如实描述，不为每个 hop 再加入 p 值门槛。

DEV 通过后，先冻结 `b*`、`a*`、四个权重端点及数据/执行身份，再一次性评分独立确认 3072 题，四个端点均保留 T32/48/64，包含未被选中的所有基线。

确认的统计单位为图实例；primary 2048 题按 hop 等权（每 hop 512，也等于按真实 n 加权）。上述最多三项使用**双侧 exact McNemar**，报告 wrong→right / right→wrong、配对点增益、95% 配对区间，并对去重后的检验做 Holm、家族 α=.05。三项方向均为正且 Holm 通过才支持联合结论；5 pp 只用于 DEV 实用筛选，不把检验事后改成 5 pp 非劣/优势检验。

同时要求候选确认点值高于所有九个基线出口及自身两个浅出口，并满足同样的简单/困难任务能力观察检查；困难题 T32 的下降仍完整披露，不能宣称已实现无代价的自适应退出。未选基线若更强，必须披露且不通过联合成功判断。**只有选定的最多三项有校正后的显著性结论**；其他出口的点值检查不能被写成“统计上胜过所有基线”，各 hop/曝光效应/同 T48 等统计均为描述性，不新增 Holm 家族。`b*` 与 `a*` 在独立确认前选定，因此不使用确认数据挑对照或出口。

确认失败时仍报告估计及区间：例如“有训练收益但没有额外循环收益”“有深出口收益伴浅出口损失”，而不是把所有部分效应抹去；这些均不等同于完整研究目标达成。本次仍是一个训练 seed 的两臂比较，独立新图确认不等于跨训练种子复现。

## 6. 功效、评估成本与停止边界

主确认每 hop 512、总 n=2048。若配对不一致比例 q 为 .2–.5，按三个检验最保守 Bonferroni 等效 α=.0167、双侧正态近似，单项约 80% 功效对应增益 **3.2–5.1 pp**。这是规划近似，不是 exact McNemar 的实际功效，也不保证三个条件及任务能力检查联合有 80% 功效；相关结构须结果后如实报告。DEV n=512 用于选择，不把显著性不足当正式无效结论。每 hop 的 512 题不用于强行确认四个单独 hop 都显著。

保留 3072 确认题，足以维持上述 primary 样本量；若沿旧的十 hop 各 512 模式，需 5120 确认题和 30,400 个总新图，增加的 d3/4 与 guard 样本不扩大 primary n。本草案优先 3072，不随结果变更。

| 成本项 | 题目 × 权重 × 出口 | 保存预测数 | 循环前向“题×轮” |
|---|---|---:|---:|
| 完整 DEV | 1280 × 4 × 3 | 15,360 | 737,280 |
| 通过后独立确认 | 3072 × 4 × 3 | 36,864 | 1,769,472 |
| 合计（不含 readiness） | — | 52,224 | 2,506,752 |

推理代理为 `Σ_T(T·A+B_other)`，只有前向，不套训练的 `R+3K`。上述 DEV/确认代理分别约 `6.37405e17 / 1.52977e18`，两者合计已约为两臂训练代理的 1.12 倍；推理无反向的显存和实际吞吐不同，不能按这比值直接换算 GPU 时间。

以已有 native-BOS 校准 256 题、T32/64、217.7 秒作**粗估锚点**，T32/48/64 的总循环与出口次数恰为该两出口的 1.5 倍，完整 DEV 约 **1.81 GPU 小时**，3072 题确认约 **4.35 GPU 小时**。5120 题确认则约 7.26 小时，多约 2.90 小时。包括所有曝光对照与中间基线，没有把它们的评估成本漏掉。

已有合成 B2×8/L256 单更新记录中 R32 forward/backward 合计 6.67 秒，R64 全更新 9.40 秒；两次运行非稳定吞吐对照，首个 Adam 分配不同。仅据此作量级外推，两臂训练约 **4.3 GPU 小时**；共同适配统一以 R32 完整单更新 9.916 秒为锚点，`9.916×256/3600≈0.71` GPU 小时，不能把它当作稳态吞吐。连同完整 DEV/确认，合计仍约 **11 GPU 小时**。建议资源规划留 **8–22 GPU 小时**的宽区间，另留模型加载、存盘、I/O/设备争用余量；不是时限承诺或货币报价。DEV 不合格时不支付确认成本。两张已分配 A100 可并行训练，但 readiness 先行、存盘与评价调度使墙钟时间不能简单除二。

在 adopted 前可复用已通过的 B2×8/L256 梯度窗口/容量/配对状态证据，只补新计划、LR前缀、恢复计数及多出口选择统计接口的新风险验证。运行出现 OOM、非有限更新、窗口不正确或持久化损坏，保留失败记录并停止；不自动覆盖重试。运行健康但最终条件失败，停止此固定深度假设，不在本轮加入课程、第三臂或提示词搜索。

## 7. 相对旧建议的收敛

- 固定 K8、固定两训练深度与恒定六难度流不变；先检验深出口训练是否有用，不把课程顺序/难度关联混进来。
- 1200/780 取代向上取 786，公开近似等工作量误差及同曝光额外成本；学习率改为相同 update 前缀，避免同曝光仍 LR 不同。
- 主出口预定 T64，删除无独立假设的 T96；T48 捕捉 Ouro 中已出现的强中间出口。
